# 图

**绘制机制图, 而非数据图.**

数据图呈现计算结果, 理解数据图须以掌握算法为前提. 机制图展现推演过程, 读者正是借由机制图理解算法机理.

判定标准: 半年后重阅此图, 能否准确回忆该算法的核心逻辑. 若无法回忆, 则说明绘图未达目的.

---

## 一、什么值得画

依据机制类型进行判断, 而非依据原论文图表数量:

- 单次测量的物理实质: 观测基准、测量对象、保留分量与舍弃分量
- 某未知量得以被消去的理论机理
- 从原始数据至最终数值的完整处理流水线, 采用分镜呈现
- 同一数据集在不同尺度或观测视角下的不同表征
- 定向物理量呈现不对称性的物理成因
- 单次干预操作的具体修改机制 (跳过特定模块、替换特定分支)

## 二、什么不值得画

- 原论文已包含的结果图 — 无需重绘, 须裁剪原图嵌入笔记, 详见"论文原图"一节
- 纯示意性的架构框图 — 凡文字单句即可清晰阐述的内容无需绘图
- 仅将公式绘制为函数曲线, 而未解释其运作机制

## 三、风格

与 vault 已有截图风格保持协调, 遵循克制原则. 全篇采用统一配色方案:

```
强调色    第一主体 / 主线
次要色    第二主体 / 对照线
灰        背景数据点
深灰      文字与主结构
```

**观察者使用抽象符号表示, 勿绘制人物形象.** 采用带中心点的圆环配以若干辐射短线, 表示"在此视角向外观测", 与 vault 内其他图表的克制风格保持一致.

## 四、排版硬规则

**关键距离在画面中必须占据显著比例.** 若点云分布过密导致待标注距离仅占画面宽度的数个百分点, 所有标注将挤压重叠. 须使用抖动网格控制间距, 避免采用纯随机分布点.

**依数值特征筛选展示对象, 而非按画面空间位置选取.** 若需清晰展现两个同心圆的差异, 应选取半径比值明显大于 1 的样本. 若仅按"位于画面中心"选取, 极易选出差异不明显的样本.

**标签须置于各自主体端点外侧.** 当两方向相近时, 若在中点施加垂直偏移, 会导致两个标签发生重叠. 端点本身具备物理间距, 将标签置于端点外侧即可自然分离.

**标签须添加不透明底色**, 避免被图中的线条与数据点遮挡.

**构型不满足要求时应通过程序搜索.** 为展示效果明显的示例, 可随机生成数千个构型按条件筛选; 若未命中, 则逐步放宽阈值. 切勿手工拼凑坐标, 亦不可迁就效果不明显的构型.

## 五、Wolfram 工具链

**源码必须经过转码处理.** wolframscript 默认按 Latin-1 编码读取文件, 直接写入中文字符将导致乱码.

```
写 figures.src.wls (UTF-8, 中文直接写)
  → python ~/.claude/skills/paper-recipe/scripts/wlsbuild.py figures.src.wls figures_gen.wls
  → wolframscript -file figures_gen.wls
```

`.src.wls` 源码文件须与笔记一同归档保存. 图表若需修改须修改源码并重新生成, 切勿直接编辑 PNG 文件.

**内核限制并发客户端数量.** 若报告 license 错误, 提示用户关闭 Wolfram GUI 客户端. 随后先运行 `wolframscript -code '1+1'` 验证运行环境可用.

**脚本须在 tmux 会话中运行.** 内核初始化耗时数十秒, 运行在 `claude-running-<项目>` 中以便用户观察执行进度.

**每张图生成后必须通过 Read 查看核验.** 未做核验等同于未完成绘制. 诸如标签重叠、圆环重合、转义字符泄漏等问题, 唯有查看图像方能检出.

## 六、真实计算优先

凡可通过模拟计算得出真实数值之处, 勿绘制示意图. 模拟所得数值须一并记入笔记正文, 供读者复算检验.

图注或正文中须明确注明模拟参数与随机数种子.

## 七、什么时候交给人手画

**同一张图排版调整超过三轮仍未达到预期, 应停止重试, 交由用户使用图形工具绘制.**

盲调坐标耗时缓慢: 无法实时预览导致每次调整均需完整渲染, 渲染后发现标签重叠再行修改, 单轮耗时一分钟; 而人工拖拽调整标签仅需数秒.

移交任务时须向用户明确提供: 图表的核心表达意图、现有的源码文件、当前渲染结果中存在的具体问题.

## 八、论文原图

除机制图外, **正文中逐图解读的原论文图表, 均须裁剪并嵌入笔记对应小节.** 笔记通篇深入讨论某张图表而读者无法直观得见时, 深层链接跳转无法取代图文并置的即时可读性.

图像裁剪切勿采用手工截屏, 须通过图注 (caption) 坐标精确计算定位, 以保证操作可复现:

```
pdftotext -bbox 找到 "Figure N:" 首词的 yMin  →  图区下界 = yMin − 5pt
图区上界 = 页顶留白 (~45pt), 或上一条 caption 末行的 yMax + 8pt
pdftoppm -png -r 200 -f <页> -l <页> -x -y -W -H 直接按像素裁 (pt × 200/72)
```

规则:

- 文件命名规范为 `<prefix>-paper-figN.png`, 以便与机制图 `<prefix>-fig-n-<slug>.png` 区分.
- **论文结果图须置于小节开头** (紧跟标题), 此规则与机制图相反 —— 鉴于整节文字均在对其进行解读, 读者需图文对照阅读. 机制图则仍应置于解释性文字之后.
- 每张图均配单行斜体说明: 图号、页码、重点观测区域 (特定曲线或异常特征).
- 附录中用于支撑批评观点的图表亦须同样裁剪嵌入, 置于引用该图的段落之后.
- 裁剪完成后必须调用 Read 核验一遍, 确保图例未被截断、周围正文未被误入.

## 九、放进笔记

```
文件名     <vault>/assets/png/<firstauthor><year>-fig-<n>-<slug>.png
引用       ![[<firstauthor><year>-fig-<n>-<slug>.png]]
分辨率     ImageResolution -> 144
```

机制图须置于其所阐述文字段落的**后方**. 须先行讲明观测要点, 随后再呈现图表.
