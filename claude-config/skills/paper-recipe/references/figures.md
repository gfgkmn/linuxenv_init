# 图

**画机制图, 不是数据图.**

数据图展示结果, 看懂它需要先懂算法. 机制图展示过程, 看懂算法靠的就是它.

判断标准: 半年后翻到这张图, 能不能想起这个算法在干什么. 想不起来就是没画对.

---

## 一、什么值得画

按机制的类型来判断, 不是按论文有几张图:

- 一次测量到底在测什么: 站在哪里, 量什么, 保留什么, 丢掉什么
- 某个未知量为什么能被消掉
- 从原始数据到最终数字的完整流水线, 分镜画
- 同一份数据在不同尺度或不同视角下的不同面貌
- 有方向的量为什么不对称
- 一次干预到底改了什么 (跳过某个模块、替换某个分支)

## 二、什么不值得画

- 论文里已有的结果图 — 不要重画, 但要裁剪原图嵌入笔记, 见"论文原图"一节
- 纯示意的架构框图 — 文字一句话说得清的不要画
- 只是把一个公式画成曲线, 而不解释机制

## 三、风格

与 vault 已有的截图风格协调, 保持克制. 固定一套配色贯穿全篇:

```
强调色    第一主体 / 主线
次要色    第二主体 / 对照线
灰        背景数据点
深灰      文字与主结构
```

**观察者用符号, 不要画小人.** 一个圆环加中心点, 外加若干短放射线, 表示"站在这里
向外看", 与 vault 里其他图的克制风格一致.

## 四、排版硬规则

**关键距离必须占画面可观比例.** 点云画得太密, 要标注的距离只有画面宽度的百分之几,
所有标注会挤成一团. 用抖动网格控制间距, 不要用纯随机点.

**按数值挑要展示的对象, 不要按画面位置挑.** 想让两个同心圆看得出区别, 就挑半径比值
明显大于 1 的样本. 按"画面中心那个点"挑, 很可能挑到一个差异看不出来的.

**标签放在各自端点外侧.** 两个方向接近时, 中点加垂直偏移会让两个标签撞在一起. 端点
本身是分开的, 标签放在端点外侧自然就分开了.

**标签加不透明底**, 否则会被线和点压住.

**构型不满足要求就搜.** 要展示一个效果明显的例子, 就随机生成几千个构型按条件筛, 筛
不到就逐步放宽阈值. 不要手工凑坐标, 也不要迁就一个效果不明显的构型.

## 五、Wolfram 工具链

**源码必须经过转码.** wolframscript 按 Latin-1 读文件, 中文直接写进去会变乱码.

```
写 figures.src.wls (UTF-8, 中文直接写)
  → python ~/.claude/skills/paper-recipe/scripts/wlsbuild.py figures.src.wls figures_gen.wls
  → wolframscript -file figures_gen.wls
```

`.src.wls` 与笔记一起留存. 图要改就改源码重跑, 不要改 PNG.

**内核限制并发客户端数.** 报 license 错误时, 让用户关掉 Wolfram GUI. 先用
`wolframscript -code '1+1'` 确认能跑.

**在 tmux 里跑.** 内核启动要几十秒, 放 `claude-running-<项目>` 里让用户看得到进度.

**每张图生成后必须 Read 一遍.** 不看就等于没画. 标签重叠、圆圈重合、转义泄漏这些问题
只有看图才发现得了.

## 六、真实计算优先

能用模拟算出真数字的, 不要画示意图. 模拟出的数值同时写进笔记正文, 读者可以复算.

图注或正文里要写清模拟参数和随机种子.

## 七、什么时候交给人手画

**同一张图重排超过三轮还没弄好, 停下来, 交给用户用图形工具画.**

盲调坐标很慢: 看不到结果就得先渲染, 渲染完发现标签撞了再改, 一轮一分钟. 人手拖一下
标签是一秒的事.

交接时给用户: 图要表达什么、已有的源文件、当前渲染出来的问题.

## 八、论文原图

机制图之外, **正文里逐图解读过的论文图, 都要裁剪出来嵌进笔记对应小节.** 笔记通篇
讨论某张图而读者看不到它, 深链跳转代替不了一眼就在眼前.

裁剪不要手工截屏, 用 caption 坐标定位, 可复现:

```
pdftotext -bbox 找到 "Figure N:" 首词的 yMin  →  图区下界 = yMin − 5pt
图区上界 = 页顶留白 (~45pt), 或上一条 caption 末行的 yMax + 8pt
pdftoppm -png -r 200 -f <页> -l <页> -x -y -W -H 直接按像素裁 (pt × 200/72)
```

规则:

- 命名 `<prefix>-paper-figN.png`, 与机制图的 `<prefix>-fig-n-<slug>.png` 区分.
- **结果图放小节开头** (紧跟标题), 与机制图相反 —— 整节文字都在解读它, 读者要
  边看图边读. 机制图仍放解释文字之后.
- 每张配一行斜体说明: 图号、页码、该看哪里 (哪条线、哪个异常).
- 附录里支撑批评的图同样嵌, 放在引用它的段落之后.
- 裁出来必须 Read 一遍, 确认没切掉图例、没带进正文.

## 九、放进笔记

```
文件名     <vault>/assets/png/<firstauthor><year>-fig-<n>-<slug>.png
引用       ![[<firstauthor><year>-fig-<n>-<slug>.png]]
分辨率     ImageResolution -> 144
```

图放在它解释的那段文字**后面**. 先讲清楚要看什么, 再给图.
