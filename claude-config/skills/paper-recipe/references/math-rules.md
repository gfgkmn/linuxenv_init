# 数学怎么讲

**读者基线**: 具备微积分、概率论与线性代数基础, 但久未运用已多有遗忘. 未接触过特定研究方向专有的数学术语.

叙述须以此基线为准. 切勿因某符号见于参考文献, 便默认读者已然知晓.

---

## 〇、讲法的顺序: 目的 → 障碍 → 应对 → 为什么有效

阐述算法、方法或统计检验时, 统一遵循四步结构:

1. **目的**: 说明其旨在解决何种问题. 篇幅为一至两句, 明确阐述阅读下文的动机.
2. **障碍**: 说明直接处理将受阻于何处. 包括哪个量无法计算、哪项假设不成立, 或哪条推导路径无法走通.
3. **应对**: 阐明具体算法与实施步骤, 详尽至足以指导代码实现.
4. **为什么有效**: 阐明该方案如何规避上述障碍 —— 数学机制置于此处.

最典型的劣质写法是以"数学内核"直接开篇: 读者尚未明晰其实际功用, 便被迫面对形式化的引理. 无论机理多么精妙, 均须置于阐明目的与操作步骤之后.

第二步最易被整体遗漏. 一旦缺失, 读者便仅知"如何操作", 却无法理解"为何必须如此设计". **方法的具体形态取决于其所绕开的障碍**; 若不交代障碍, 每一项设计抉择都会沦为凭空设立的生硬规则. 因此, 凡遇非显而易见的设计抉择, 应先展现直接路径所遇之阻碍, 再引出绕行方案.

自查判据: 若将当前步骤替换为更直接的做法会产生何种后果? 若无法明确回答"会受阻于何处", 即表明尚未交代障碍环节.

须注意, 此四步法属于写作的**内在逻辑骨架, 而非显式的小标题**: 切勿将"是什么 / 怎么做 / 为什么"机械地列为小标题, 正文各段依此逻辑自然推进即可.

同样的规范亦适用于微观段落: 在开展具体计算或推导时, **首句须先点明该推导旨在回答什么问题**, 尾句则须将推导结论重新接回主线叙事. 读者在阅读任一段落的开头时, 均应能明确说出"该段文字在此处承担何种功能"; 若无法判定, 则说明该段论述处于悬空状态.

## 〇之二、交代不可得量

技术笔记往往详述方法求解了什么, 却极少交代其**无法直接求得什么**. 然而, 那个无法获取的未知量往往正是该方法得以确立的根本理由, 即前文所述障碍的具体形态.

推导完成后须系统梳理各项参数: 明确哪些量源自实际测量, 哪些属于已知常数, 哪些**未知且无法直接获取**. 进而阐明该方法如何在缺失该未知量的前提下完成推断. 常见的应对路径有三条: 仅依赖相对量、仅检验某物理量是否保持恒定, 以及通过构造比值使未知量相互抵消.

**必须严格区分"无法计算"与"无需计算".** 混淆二者会导致方法论证的逻辑前提出现偏差: 尽管最终结论可能依然成立, 但读者依此开展工程实现时易偏离原意. 判定准则是对涉及的每个量逐一核实: "该量究竟是无法获取, 还是虽可获取但在当前框架下无需使用".

## 一、每个符号逐个解释

**每个符号均须在首次出现处予以阐明, 并尽可能赋予几何直观.** 即使含义直观亦须简要带过 ("$m$ 是抽稀倍数, 即只保留 $1/m$ 的点"), 含义非显明者则须充分展开. 给出公式块后须整体复核: 确保公式中出现的每个符号均有明确定义. 概无例外.

解释须涵盖:

- 该符号**代表什么** (概率密度 / 常数 / 秩次 / 概率分布 / 矩阵等)
- **取值范围或量纲**
- 凡可给出经验值的**均须给出具体数值**

最易遗漏的是形如"仅与某参数相关的常数"—— 其在公式中往往并不显著, 却常是分离或显化待估参数的关键节点. 若不予说明, 读者将难以理解结论推导的合理性.

## 二、常数是怎么来的

公式中出现的归一化系数与量纲因子等常数, 均须说明其来历与构造机理: 阐明为何取此特定数值, 以及若取其他数值会导致何种偏差.

唯有交代清楚, 读者方能理解所得数值的实际意义; 若不予阐明, 其仅为孤立的数字.

典型的说明方式是分析边界情形: 考察在理想极限与完全随机两种极端状态下该指标的理论取值, 由此推导为何该系数必须设定为特定数值以使其落在预期的规范化区间内.

## 三、推导不跳步

**严禁将多步代数推导压缩为单句概括.** 诸如"移项取对数整理可得"之类的略写不可接受.

推导过程须采用结构化对齐块呈现, 并逐行注明变换操作:

```
原式                        说明
变形一                      移项
变形二                      两边取对数
变形三                      整理成线性形式
```

推导中同样须完整保留以下环节:

- 由一般形式代入特例的具体步骤, 明确指出代入后哪些项退化为 1 或 0
- 泰勒展开或渐近近似的完整表达式, 须显式写出被略去的高阶项并阐述忽略的理论依据
- 闭式解的导出过程 (例如对目标函数求导并令导数等于零)
- 量级估计的完整推导过程, 不可仅给出结论
- 推导中所援引的经典定理与基础事实, 须在调用处给出提示并**显式指明所用工具或定理的正式名称** (如累积分布函数的定义、生存函数与 CDF 的互补关系、单调变换不改变事件发生概率、指数分布的生存函数形式、全概率公式、极大似然估计的含义). 根据读者基线设定, 此类知识读者曾学习过但已遗忘 —— 读者具备具体运算能力, 所缺失的是明确"当前步骤调用了何种理论工具"; 若不显式指明工具名称, 推导逻辑链条即告中断

**推导篇幅过长时须进行模块化拆分.** 若基础数学铺垫的篇幅超出主线叙事, 应拆分为两层架构: 主干部分用一句话概括核心结论及其应用目的; 完整推导过程则单独收纳于可折叠的辅助模块中 (例如在 Obsidian 中使用 `> [!note]- 标题` 语法创建默认折叠的 callout 块). 略读读者跳过该模块不影响理解核心主线, 精读读者亦能获取无跳步的完整推导.

## 四、极小规模数值示范

**每一套估计流程均须配以一套极小规模的手算范例.** 样本规模应控制在足以完整列出全部中间结果的程度.

范例须展示:

1. 起始的输入原始数值
2. 各步骤变换后的中间结果, 并制表呈现
3. 最终计算数值
4. **边界情况与异常值的处理逻辑**

第 4 项最易遗漏, 却往往是工程实现中最先暴露缺陷之处: 例如某特定取值会导致对数运算发散、某索引下标越界, 或某类样本必须剔除. 论文通常不写此类细节, 但若不写清楚则算法无法正常运行.

**构造的示范数据必须契合该变量的真实统计分布, 方差量级尤须准确.** 人工构造的数值往往过于规整, 而过于规整的数据会误导读者的方差直觉, 导致其写出错误的判据 —— 例如将本需进行统计检验的判断写成与某数值的等值比较, 遇到真实数据便发生误判.

数据构造完成后须反问复核: 该组数值的离散程度与该变量的理论标准差是否吻合? 若不吻合则须重新构造.

## 五、假设为什么成立

论文中出现"假设 X"之处, 统一按三段式展开:

- **假设是什么**
- **为什么成立** — 在何种条件下该近似是合理的
- **什么时候垮掉** — 当参数推移至何种程度时该假设不再成立

第三项给出了方法的适用边界. 论文通常略去不提, 但它直接决定了该方法能否被安全推广并应用至具体场景中.

## 六、能算的就算给自己看

抽象论证不如一段可运行的数值模拟直观. 论文中依靠文字定性论证的性质, 只要能够构造出最小例子, 均应通过数值计算验证一次, 并将具体数值记录于笔记中.

具体的数值便于读者直观评估效应量的大小, 也为其独立复算提供了基准. 仅罗列结论则无法达成这两点.

数值模拟须注明参数配置与随机数种子, 否则不可复现.

**若模拟结果与预期机制不符, 应排查参数设定, 切勿修改叙述.** 参数设定不当的模拟可能会证明相反的结论, 直接写入笔记将导致事实性错误.

## 七、不要用比喻代替数学

在中文技术与学术写作中, 抽象数学对象不做具象实物化比喻. 详见 `stop-slop-zh` 中关于翻译腔的规范.

英文科技文献习惯使用空间位置与肢体动作隐喻描述数学对象 (如 sits in / spans / collapses onto), 直接直译为中文显得生硬失范. 应直接阐明精确的数学关系本身: 例如谁是谁的指数、谁决定谁的增长率、自由度增大还是减小等.

比喻可用于辅助建立直观认知, 但**必须同时给出严谨的数学表述**, 严禁仅提供比喻而略去数学定义.
