# 数学怎么讲

**读者基线**: 学过微积分、概率论、线性代数, 但已经很多年没用, 忘得差不多了. 论文里
那些方向专有的数学名词没接触过.

按这个基线讲. 不要因为符号在论文里出现过就默认读者认识它.

---

## 〇、讲法的顺序: What → How → Why

讲一个方法或检验, 固定按三步走:

1. **What**: 它是什么, 要回答什么问题. 一两句, 让读者知道为什么要往下看.
2. **How**: 具体怎么做, 操作到能写代码.
3. **Why**: 为什么这样做是对的 —— 数学机制放在这里.

最常见的写坏方式是拿"数学内核"开场: 读者还不知道这东西干什么用, 先被一个引理
砸在脸上. 机制再漂亮也要排在目的和操作之后.

注意这是写作时**内在的骨架, 不是显式的标签**: 不要把"它是什么 / 怎么做 / 为什么"
当题头写出来, 段落按这个顺序自然推进即可.

同样的纪律下沉到段落: 一段算账或推导, **第一句先说它在回答哪个问题**, 结尾把
结论接回叙事. 读者在任何一段的开头都应该答得出"这段话放在这里想干什么"; 答不出,
就是这段悬空了.

## 一、每个符号逐个解释

**每个符号在第一次出现的地方就解释, 而且要给几何意义.** 显而易见的也一句带过
("$m$ 是抽稀倍数, 即只保留 $1/m$ 的点"), 不显而易见的展开. 公式块之后再整体
核对一遍: 块里出现过的每个符号都有解释. 没有例外.

解释要包含:

- 这个符号**是什么** (密度 / 常数 / 排名 / 分布 / 某个矩阵)
- **取值范围或量纲**
- 能给具体值的**给具体值**

最容易漏的是那种"只跟某个参数有关的常数"—— 它在公式里不起眼, 但常常正是把待估量
暴露出来的地方. 不解释它, 读者看不出结论为什么成立.

## 二、常数是怎么来的

公式里出现的归一化系数、量纲因子, 都要说明来历: 为什么是这个数, 换成别的会怎样.

讲清楚了, 读者才知道算出来的数值意味着什么; 不讲, 它只是个数字.

典型做法是给出边界情形: 在最理想和最随机的两种极端下, 这个量分别等于多少, 于是系数
必须取成某个值才能落进预期区间.

## 三、推导不跳步

**不要把多步代数压成一句话.** "移项取对数整理可得"是耍赖.

写成对齐的块, 每一步标注做了什么:

```
原式                        说明
变形一                      移项
变形二                      两边取对数
变形三                      整理成线性形式
```

同样要保留:

- 从一般式代入特例的那一步, 包括代入后哪些项变成 1 或 0
- 泰勒展开或近似的完整式子, 含被丢掉的那些项, 以及丢掉的理由
- 闭式解怎么来的 (对目标函数求导令其为零)
- 量级估计的推导, 不要只给结论
- 用到的教科书事实, 在使用处给一句唤醒提示, 并**点出工具的名字** (累积分布的定义、
  生存函数与 CDF 互补、单调变换不改变事件、指数分布的生存函数形式、全概率公式、
  极大似然的含义). 按读者基线, 这些他们学过但忘了 —— 操作本身会做, 缺的是
  "这一步在调用哪件工具"那句话; 不点名, 整步推导就断了

**推导太长时模块化.** 数学基础铺垫占的篇幅一旦超过主线本身, 拆两层: 主干里用
一句话说清结论是什么、拿来干什么; 完整推导单独放进可跳过的折叠模块 (Obsidian 写
`> [!note]- 标题` 即默认折叠的 callout). 不想看的读者跳过不影响主线, 想看的读者
得到不跳步的完整版本.

## 四、极小规模数值示范

**每个估计流程都要有一遍手算.** 规模取到能把中间结果全部列出来为止.

要展示:

1. 起始的原始数字
2. 每一步变换后的中间结果, 列成表
3. 最终数值
4. **边界情况怎么处理**

第 4 条最容易漏, 而它往往是实现时第一个踩的坑: 某个取值会让对数发散, 某个下标会越界,
某个样本必须丢掉. 论文一般不写, 但不写清楚就跑不通.

## 五、假设为什么成立

论文写"假设 X"的地方, 按三段写:

- **假设是什么**
- **为什么成立** — 在什么条件下这个近似是合法的
- **什么时候垮掉** — 参数推到什么程度这个假设就不再成立

第三条给出方法的适用边界. 论文通常不写, 但它决定了别人能不能安全地把这个方法用到
自己的场景上.

## 六、能算的就算给自己看

抽象论证不如一段能跑的模拟. 论文里靠文字论证的性质, 只要能构造出最小例子, 就构造出来
算一遍, 把数字写进笔记.

数字能让读者自己判断效应有多大, 也能让他们复算. 只写结论就做不到这两点.

模拟要写清参数和随机种子, 否则不可复现.

**模拟结果和想讲的道理不符时, 检查参数, 不要改叙述.** 参数选得不合适的模拟会证明相反
的事情, 直接放进笔记就是错的.

## 七、不要用比喻代替数学

中文技术写作里, 抽象对象不做实物化的比喻. 详见 `stop-slop-zh` 的翻译腔规则.

英文习惯用空间和身体动作描述数学对象 (sits in / spans / collapses onto), 直译进中文
会很怪. 要说数学关系本身: 谁是谁的指数、谁决定谁的增长率、自由度变大还是变小.

比喻可以用来建立直觉, 但**必须同时给出数学表述**, 不能只给比喻.
