# 审稿代理: 交付前的固定一站

生成与审稿分离的理由是一条不对称: **生成需要上下文, 审稿需要没有上下文.**
生成侧离不开本会话积累的详略校准、已核事实和链接表; 审稿侧恰恰相反 —— 写作者
读自己的产物三遍也不觉得刺眼, 因为缺陷在他的上下文里已被驯化. 审稿代理拿到的
只有规则和草稿, 规则在它上下文的最顶端, 而且它是读着规则做识别, 不是在生成
压力下回忆规则.

用户已授权 (2026-08-28): 本站的审稿代理属于流程固定环节, 不必每次请示.

## 分工

生成侧 (主会话) 只守两个零成本习惯, 其余检查全部交给审稿代理:

- 段落首句交代意图 (math-rules 第〇节)
- 符号首现即释 (math-rules 第一节)

## 代理设置

- 类型: 用 `zh-reviewer` (定义在 `~/.claude/agents/zh-reviewer.md`, 固定
  `model: claude-opus-4-6`). 换不同权重的模型审稿是有意为之: 生成侧与审稿侧
  同权重时文体先验相同, 盲区共享; Opus 4.6 的中文语感先验不同, 恰好补上
  规则清单覆盖不到的部分 (任务书里对应"语感项"一节). **不要用 fork** ——
  fork 继承主会话上下文且强制同模型, 两头都毁掉审稿的价值.
- **必须走会话内 Agent 工具, 禁止 headless `claude -p`**: 用户环境设有
  ANTHROPIC_API_KEY, headless 调用会静默走 API 计费; 会话内子代理走订阅额度.
  用户明确要求只走订阅.
- 新建的 agent 类型注册表可能要到下一轮才刷新; 若报 "Agent type not found",
  等一轮再试, 不要绕道 CLI.
- 输入 (只给这四样, 其余一概不给):
  1. stop-slop-zh 的 SKILL.md
  2. paper-recipe 的 math-rules.md
  3. delivery.md (链接与结构规则部分)
  4. 待审草稿
- 明确禁止: 打开笔记里的 bookends 深链; 读其他文件; 修改任何文件.
- **只许用 Read 工具, 禁用 Bash**: 后台代理答不了权限提示, 一次 Bash 拦截就会
  让它无声死掉, 不留报告.
- **待审稿先拷贝到工作目录再交给代理**: vault 在 iCloud 路径下, 不在授权目录内.

## 必交的五个产物

产物式检查强迫覆盖发生, 这是把检查从 grep 升级到语义层的关键:

1. **逐公式符号对照表**: 公式 → 每个符号 → 解释它的原句; 缺失标 [缺].
2. **逐段意图检查**: 每段一句话概括它在回答什么; 概括不出标 [悬空].
3. **回译测试**: 抽 8 个实质性句子, 给英文回译与判定, 翻译腔给改法.
4. **链接审计**: 对其他笔记的裸提及; 指向小节的引用是否用标题级链接.
5. **分级 findings**: 严重 / 中等 / 轻微, 每条给 位置 + 规则依据 + 建议改法;
   全过的项也要明确说"无发现".

要求从严: 宁可多报待人工复核, 不要漏报.

## 语体定稿 (审稿修订之后, 交付之前)

内容与语言分两审: zh-reviewer 管内容、数学与链接; **语体定稿交给
Gemini 3.7 Flash** (用户 2026-08-28 确立, 其文风即语体标准). 调用方式:

```bash
agy -p "$(/bin/cat 提示词文件)" --model gemini-3.7-flash-high > rewrite-gemini.md
```

提示词骨架: "重写成你自己会写的中文, 不给风格规则" + 硬约束清单 (公式/推导/数值
信息量不减; 深链原样且附着原句; wiki 链接、图嵌入、frontmatter、标题行、折叠块
结构原样; 事实数字结论不得改动新增; 半角标点; 禁用工具, 直接输出全文).

**已知的坑**:
- agy 走用户的 Google AI Pro 订阅 (OAuth), 严禁改用 GEMINI_API_KEY (预付额度).
- 折叠块 (`> [!note]-`) 常被原样跳过, 需要单独抽出再跑一次, 拼回.
- Gemini 会擅自拔高结论 ("验证通过"→"充分验证了有效性", "仍只有"→"严格控制在"),
  定稿后必须扫一遍评价性副词与形容词, 越界处改回. 注意"充分小""显著性"这类
  数学术语不算拔高, 不要误改.
- Gemini 会删掉解释性的转折与目的从句 —— 那些交代"为什么要这样表述""这一步为
  后文做什么准备"的话, 在它眼里是冗余, 但恰恰是读者最需要的. 定稿后逐段与原文
  比对, 凡丢失的说明性从句一律补回.
- 长文在 tmux 里跑, stdout 落文件 (stderr 留在面板可见).

**定稿后核验清单** (逐项跑, 全过才能覆盖 vault):
深链数不变且逐条格式完好; 标题行 diff 为空; 图嵌入 diff 为空; frontmatter diff
为空; 折叠块行数与结构一致; 数字集合对比无实质漂移 (等价表述如"四分之三"↔"75%"
允许); 备份现行版后再覆盖.

## 收尾

- 主会话按 findings 修订; 误报直接弃置, 不必回禀代理.
- 修订量大时可对改动部分再跑一轮复审 (可选).
- 代理与主会话同权重, 文体先验相同 —— 它降低盲区共享, 不消灭.
  **它不替代用户终审**, 目标是把用户每轮要抓的错压到一两类.
- 成本量级: 一趟三五万 token, 约占一篇笔记总成本一成.
