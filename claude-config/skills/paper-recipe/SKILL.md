# Paper to Understanding and Implementation Recipe

一篇论文最后要变成两样东西: 一份看得懂的中文笔记, 一份照着能复现的清单.

## 两种模式

开工前先问用户要哪种, 不要自己猜.

**提取模式** — 已有人与模型的对话记录, 或者只需要一份查阅用的参考笔记. 六个阶段
全自动跑, 覆盖性检查全开. 对话记录只当草稿, 事实逐条回原文核对 (见三条前提).

**精读模式** — 冷论文, 用户要真正读懂它. 阶段 2 和阶段 4 改成对话式, 在关键处
停下来:

- 检查点永远放在"设定已知、结果未知"的节点: 先讲完背景、核心问题、实验设计
  (第 1 项通俗综述, 不含结果), 才能发第一个预测 —— 没有足够信息的预测不是校准,
  是为难人. 对话记录只深入过方法时, 论文层面的背景要当作全新内容讲.
- 讲推导或实验结果之前, 先请用户预测结论、曲线形状或量级 (cooperation.md 的
  PREDICT). 预测错的地方, 就是笔记要写深的地方.
- 出题可以不完美, 提问的过程本身就有价值, 不要因为怕出坏题就不出题. 真正要防
  的是**答非所问**: 用户的回答或追问透露出他心里的比较对象时, 先确认"你说的 X
  指的是哪一个", 对齐参照系再展开 —— 在错误的参照系上讲得越多, 浪费越大. 题目
  确实不成立时直接说一句, 换下一题即可.
- 遇到关键设计决策, 先问用户"为什么这样做应该有效" (THINK FIRST), 再给论文的答案.
- 用户追问过几轮的概念写深, 一遍过的概念写浅. 笔记该写什么 = 论文 − 读者已知,
  详略分布本身就是对话的产物. 注意"深浅"以**当时的费力程度**为准, 与用户现在
  是否已掌握无关 —— 反复纠缠过才懂的内容, 未来忘得最快, 必须完整进笔记,
  不能以"已经懂了"为由略写. 但**写深不等于照抄对话**: 对话费力的原因可能是内容
  真难, 也可能是当时讲解得差 (拖沓、跳步本身就是证据). 无论哪种, 进笔记前都要
  按 math-rules 重新组织成干净的推进, 不搬对话原文.

全自动跑完的结果, 是一份用户没读过的论文的漂亮笔记; 精读模式存在的意义就是避免这个.

## 三条前提

**先建引用基础设施, 再写笔记.** 深链是后面所有引用的地基, 补建的成本远高于先建.

**每一条事实都要回原文核对.** 与模型的对话记录是草稿. 它可能把推测写成结论, 可能漏掉
作者自己的保留意见, 也可能把论文的次要表述当成主要论点. 写进笔记之前逐条查原文.

**语言走 skill, 不要凭记忆.** 中文调 `stop-slop-zh`, 英文调 `stop-slop`.

## 六个阶段

### 阶段 1 建立引用基础设施

拿到 PDF 先做这一步. 详见 `references/delivery.md`.

1. 抽全文与页码地图.
2. 导入文献管理器, 拿到条目 id.

注意: claims.json 和深链**不在这一步**. 要引用哪些结论, 读完论文才知道,
它们属于阶段 6.

**验收**: 页码地图覆盖全部页; 文献管理器里能查到该条目.

### 阶段 2 按顺序问论文

按 `references/reading-protocol.md` 走: 先判论文类型 (第 0 项), 再按十项走, 顺序
不要打乱; 方法型论文另启用第 11 项 (baseline 公平性).

精读模式下本阶段是对话式的, 检查点见"两种模式".

**验收**: 类型已判定; 各项都有答案, 每个答案都能指到原文页码.

### 阶段 3 采集数据与实现细节

按 `references/data-checklist.md` 逐项填.

**验收**: 清单无空项. 论文确实没给的写"论文未给", 不要留白, 也不要猜.

### 阶段 4 数学

按 `references/math-rules.md`. 核心三条: 每个符号逐个解释, 推导不跳步, 极小规模数值
示范走一遍. 精读模式下, 展开推导之前先请用户预测 (见"两种模式").

**验收**: 每个公式块下面, 块里出现过的符号都有解释; 公式里的常数都说明了来历.

### 阶段 5 图

按 `references/figures.md`. 画机制图, 不是数据图; 另把正文解读过的论文原图裁剪
嵌入 (含附录里支撑批评的).

**验收**: 每张机制图单独看能想起对应的算法; 正文讨论过的每张论文图都已嵌入;
所有图都渲染出来看过, 确认没有标签重叠、没切掉图例.

### 阶段 6 成文与交付

先建深链, 再写正文:

1. 从阶段 2-5 的产出里整理 claims.json: 每条要引用的结论配一个锚定短语和页码提示.
2. 把高亮注入 PDF 副本, 挂到文献管理器条目上, 读回深链存 links.json.
3. 正文用占位符引用, 最后统一替换. 详见 `references/delivery.md`.

结构按认知顺序. 主体是 (a) 问题是什么 (b) 背景 (c) 方法 (d) 实验怎么设计
(e) 实验证明了什么, 读者第一遍要能顺着走完, 中途不被"但是这里有问题"打断.

```
(开篇: 论文问什么 + 作者自己的答案, 不含你的评价)
1. 问题与背景
2. 方法
3. 实验设计与数据集
4. 实验结果
—— 以上是论文本身, 以下是评价 ——
5. 与相关工作的关系
6. 局限与批评           含原文的排版和图表错误
7. 复现清单
(可选) 与其他研究方向的对应
```

**评价性内容一律放在主体之后.** 主体里确实需要提醒的地方, 留一句指路 (`注意 §6.2`),
不要展开.

生成时只守两个零成本习惯 (段落首句交代意图, 符号首现即释), 其余检查交给
**审稿代理** —— 草稿完成后, 起一个不带本会话上下文的通用代理做对抗性审读,
任务书与授权见 `references/review-agent.md`; 按 findings 修订后, 交
**Gemini 3.7 Flash 做语体定稿** (工序与核验清单同见 review-agent.md), 最后按
`references/delivery.md` 做交付校验.

**验收**: claims 全部命中, 占位符零残留; 审稿代理已跑且 findings 已处理;
其余见 `references/delivery.md` 的交付清单.

## 已知的坑

| 坑 | 症状 | 处理 |
|---|---|---|
| wolframscript 按 Latin-1 读源码 | 中文变乱码 | 用本 skill `scripts/wlsbuild.py` (调用时写全路径 `~/.claude/skills/paper-recipe/scripts/`) 转成 `\:XXXX` 转义 |
| Wolfram 内核限制并发客户端数 | 报 license 错误 | 各客户端已改用 wolfram-lazy 代理 (按需拉起, 空闲释放), 常态下不应再发生. 若复现: `~/.claude/scripts/wolfram-free.sh` 看占用者, 加 `kill` 清理; GUI 开着也占一席 |
| Obsidian 不解析行内 HTML 里的 markdown | `<sup>[p.1](url)</sup>` 渲染成字面文本 | 写成 `[<sup>p.1</sup>](url)`, 链接在外层 |
| 文献管理器只给已有批注生成深链 | `link` 字段为空 | 先 attach PDF 再 extract |
| 图中关键距离占画面比例太小 | 标注全挤成一团 | 点云放稀, 或按数值挑观察点 |
| 图的标签互相压住 | 两个方向接近时偏移会重合 | 标签放到各自端点外侧, 或换一个构型 |
| 只验证了 URL 能解析 | 在 Obsidian 里其实不可点 | 验渲染, 不是验解析 |

## 成长规则

协议没抓到而人抓到的问题, 事后固化成一条机械检查, 写进对应的 reference 文件.

判断的直觉无法复制, 它的产物可以: 一次"读起来不对劲"的捕获, 沉淀成一条"逐条比对
X 与 Y"的检查, 下次不再依赖直觉. 本 skill 的坑表和各清单都是这样长出来的, 以后也
这样长.

## 什么时候把图交给人手画

Wolfram 适合能算出来的图. 纯示意图靠盲调坐标, 改一轮就要重新渲染一次, 迭代很慢.

**同一张图重排超过三轮还没弄好, 停下来, 交给用户用图形工具画.** 人手拖一下标签是
一秒的事. 交接时说清楚图要表达什么, 并把已有的源文件给他.

无论谁画, 图源文件都与笔记同存, 永远可重新编辑. 要改图就改源码重跑, 不要改 PNG.
