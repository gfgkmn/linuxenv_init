# Paper to Understanding and Implementation Recipe

一篇论文最终应沉淀为两项成果: 一份逻辑清晰的中文笔记, 以及一份可供直接复现的操作清单.

## 两种模式

执行前须先向用户确认所需模式, 切勿自行推断.

**提取模式** — 适用于已有用户与模型的对话记录, 或仅需查阅用参考笔记的情形. 全流程自动化执行六个阶段, 全面开启覆盖性检查. 对话记录仅视作草稿, 涉及的所有事实均须逐条返回原文核对 (参见三条前提).

**精读模式** — 适用于初次接触且用户需要彻底读懂的论文. 阶段 2 与阶段 4 调整为交互对话形式, 并在关键节点暂停推进:

- 交互检查点始终设于"设定已知, 结果未知"的节点: 须在完整阐述背景, 核心问题与实验设计 (即第 1 项通俗综述, 且不包含实验结果) 之后, 方可发起首次预测 —— 缺乏充分上下文信息的预测无法起到认知校准作用, 徒增理解负担. 若既有对话记录仅深入了方法细节, 论文层面的背景仍须视作全新内容完整讲解.
- 在展示理论推导或实验结果前, 须先引导用户预测结论走势, 曲线形态或数量级 (参见 cooperation.md 中的 PREDICT). 预测出现偏差之处, 即为笔记需要重点详述之处.
- 设问允许不尽完善, 提问过程本身即具备认知价值, 切勿因顾虑题目质量而放弃设问. 核心防范在于**答非所问**: 一旦用户的回答或追问暴露出其潜在的参照基准, 须先确认"此处所指的 X 具体为何者", 对齐参照系后再行展开 —— 脱离正确参照系的阐述越多, 认知浪费越大. 若题目确不成立, 直接说明并切换至下一题即可.
- 遇到关键设计决策时, 须先引导用户思考"该设计为何应当有效" (THINK FIRST), 随后再给出论文中的论述.
- 凡经历多轮追问的概念须予详述, 一遍理解的概念宜从简略. 笔记应当记录的内容 = 论文信息 − 读者已有认知, 其详略分布本就是交互对话的直接产物. 须注意, 详略程度严格以**当时的费力程度**为准, 与用户当前是否已掌握无关 —— 经反复讨论方告理解的内容未来遗忘最快, 必须完整写入笔记, 绝不可因"当下已懂"而简略带过. 但**写深不等于照抄对话**: 交互费力既可能源于内容本身的固有难度, 亦可能归咎于此前讲解不当 (表述拖沓或推导跳步即为明证). 无论何种情形, 写入笔记前均须依照 math-rules 重新组织为严密清晰的逻辑推进, 严禁直接搬用对话原文.

全自动运行的最终产物, 往往只是一份用户未曾真正读懂的精致笔记; 精读模式存在的意义即在于避免这一结果.

## 三条前提

**先建引用基础设施, 再写笔记.** 深层链接是后续所有引用关系的基石, 事后补建的成本远高于预先构建.

**每一条事实都要回原文核对.** 与模型的对话记录仅具草稿性质. 其中可能将推测记作结论, 可能遗漏作者本人的保留意见, 亦可能将次要表述误作主要论点. 写入笔记前须逐条对照原文核查.

**语言走 skill, 不要凭记忆.** 中文调用 `stop-slop-zh`, 英文调用 `stop-slop`.

## 六个阶段

### 阶段 1 建立引用基础设施

获取 PDF 后首先执行此步骤. 详见 `references/delivery.md`.

1. 提取全文文本并生成页码映射表.
2. 导入文献管理器, 获取条目 id.

注意: claims.json 与深层链接**不在这一步**. 需引用的具体结论须待研读全文后方能确定, 属于阶段 6 的工作范畴.

**验收**: 页码映射表完整覆盖全部页面; 文献管理器中可准确检索到该条目.

### 阶段 2 按顺序问论文

严格依据 `references/reading-protocol.md` 执行: 优先判定论文类型 (第 0 项), 随后依序执行其余十项, 严禁打乱顺序; 若为方法类论文, 须额外启用第 11 项 (baseline 对比公平性).

精读模式下本阶段采用交互对话形式, 检查点设置参见"两种模式".

**验收**: 论文类型已明确判定; 各项均已完成解答, 且每个答案均能精确定位至原文页码.

### 阶段 3 采集数据与实现细节

依据 `references/data-checklist.md` 逐项填报.

**验收**: 清单无任何遗漏项. 原文确未提供的信息须明确标注"论文未给", 严禁留白, 亦不得主观臆测.

### 阶段 4 数学

遵循 `references/math-rules.md`. 核心原则包含三项: 逐一解释所有数学符号, 推导过程严禁跳步, 辅以极小规模的具体数值算例演示. 精读模式下, 展开公式推导前须先引导用户做出预测 (参见"两种模式").

**验收**: 每个公式块下方均对块内出现的全部符号作出解释; 公式中所含常数均已阐明其具体来源.

### 阶段 5 图

遵循 `references/figures.md`. 绘制机制原理图而非统计数据图; 此外须裁剪并嵌入正文中解读过的论文原图 (包含附录中用于支撑批评观点的图表).

**验收**: 每张机制图独立观察时均能清晰对应相应算法; 正文讨论过的每张论文原图均已嵌入; 全部图表均已实际渲染检查, 确认无标签重叠且图例显示完整.

### 阶段 6 成文与交付

须先建立深层链接, 随后撰写正文:

1. 基于阶段 2-5 的产出整理 claims.json: 为每条拟引用的结论配置一个锚定短语及页码提示.
2. 将高亮批注注入 PDF 副本并关联至文献管理器条目, 读取生成的深层链接存入 links.json.
3. 正文使用占位符引用, 最终统一替换. 详见 `references/delivery.md`.

结构依认知顺序组织. 主体框架包括 (a) 核心问题 (b) 研究背景 (c) 方法原理 (d) 实验设计方案 (e) 实验验证结论, 确保读者初次阅读即可流畅通读, 中途不被评判性插话打断.

```
(开篇: 论文问什么 + 作者自己的答案, 不含你的评价)
1. 问题与背景
2. 方法
3. 实验设计与数据集
4. 实验结果
—— 以上是论文本身, 以下是评价 ——
5. 与相关工作的关系
6. 局限与批评           含原文的排版和图表错误
7. 复现清单
(可选) 与其他研究方向的对应
```

**评价性内容一律放在主体之后.** 主体中若确需提示, 仅保留单句指引 (`注意 §6.2`), 严禁展开论述.

生成时仅须维持两项零成本习惯 (段落首句交代意图, 符号首次出现即予界定), 其余质量检验交由**审稿代理**完成 —— 初稿完成后, 启动一个不携带当前会话上下文的通用代理开展对抗性审读, 任务书与授权机制详见 `references/review-agent.md`; 依据 findings 完成修订后, 提交 **Gemini 3.7 Flash 做语体定稿** (具体工序与核验清单同见 review-agent.md), 最终依据 `references/delivery.md` 执行交付校验.

**验收**: claims 全部命中, 占位符零残留; 审稿代理已运行且 findings 已完成处理; 其余项参见 `references/delivery.md` 的交付清单.

## 已知的坑

| 坑 | 症状 | 处理 |
|---|---|---|
| wolframscript 默认以 Latin-1 读取源码 | 中文显示为乱码 | 使用本 skill 提供的 `scripts/wlsbuild.py` (调用时须指定完整路径 `~/.claude/skills/paper-recipe/scripts/`) 转换为 `\:XXXX` 转义字符 |
| Wolfram 内核限制并发客户端数 | 报 license 错误 | 各客户端已改用 wolfram-lazy 代理 (按需拉起, 空闲释放), 常态下不应再次发生. 若复现: 运行 `~/.claude/scripts/wolfram-free.sh` 查看占用进程, 附加 `kill` 清理; GUI 进程开启亦会占用连接席位 |
| Obsidian 不解析行内 HTML 内部的 markdown | `<sup>[p.1](url)</sup>` 被渲染为字面文本 | 改写为 `[<sup>p.1</sup>](url)`, 链接置于外层 |
| 文献管理器仅为已有批注生成深链 | `link` 字段为空 | 先执行 attach PDF, 随后执行 extract |
| 图中关键距离占画面比例过小 | 标注相互挤压重叠 | 稀疏化点云, 或依据数值特征选取观察视角 |
| 图中标签相互遮挡 | 方向相近时偏移位置重合 | 将标签置于各自端点外侧, 或调整几何构型 |
| 仅验证了 URL 可解析 | 在 Obsidian 实际界面中无法点击 | 须检验实际渲染效果, 而非仅检验语法解析 |

## 成长规则

凡交互协议未能捕获而由人工审阅发现的问题, 事后均须固化为确定的机械检查项, 写入对应的 reference 文件.

直觉判断无法直接复现, 但其经验产物可以复现: 一次"阅读直觉异常"的捕获, 沉淀为一条"逐条比对 X 与 Y"的明确检查项, 后续不再依赖主观直觉. 本 skill 的问题速查表与各项清单均依此机制演进, 后续亦须按此模式持续积累.

## 什么时候把图交给人手画

Wolfram 适用于可通过数值计算生成的图表. 纯原理示意图若依赖反复盲调坐标参数, 每次修改均需重新渲染, 迭代效率极低.

**同一张图重排超过三轮还没弄好, 停下来, 交给用户用图形工具画.** 人工拖拽调整标签仅需数秒. 移交时须清晰说明图表欲表达的内容, 并提供已有的源文件.

无论制图主体为何, 图表源码文件均须与笔记一同归档保存, 确保随时可重新编辑. 后续修改图表须通过修改源码重新生成, 严禁直接编辑 PNG 图像.
